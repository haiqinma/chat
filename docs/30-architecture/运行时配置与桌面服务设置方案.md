# 运行时配置与桌面服务设置方案

状态：方案已确定，桌面设置页和本地持久化覆盖尚待实现。  
更新日期：2026-09-26

## 1. 目标

部署构建参数和应用运行配置分开管理。Web 运维人员通过服务器 `.env` 配置运行中的 Web 实例；桌面用户通过应用设置页面调整自己需要连接的服务，不要求编辑文件或重新安装应用。

## 2. 配置边界

| 来源         | 用途                                                         | 修改后生效方式                         |
| ------------ | ------------------------------------------------------------ | -------------------------------------- |
| `.env.build` | 构建工具、版本、签名，以及桌面包首次启动使用的公开服务默认值 | 重新构建/发包                          |
| `.env`       | Web standalone 服务端私有配置和公开运行配置                  | 重启 Web 服务；浏览器重新加载          |
| 桌面设置页   | 当前桌面用户可覆盖的服务地址                                 | 保存后由桌面端运行时配置覆盖包内默认值 |

`.env.template` 是 Web 运行时 `.env` 的模板；`.env.build.template` 是构建输入模板。模板本身不会被应用动态读取，也不能在两份实际文件之间复制同一环境的配置。

构建入口统一遵循：

```text
命令行 / CI 环境变量
    ↓
.env.build
    ↓
代码默认值
```

Next 会自动扫描标准 `.env` 文件，构建加载器会显式隔离这些 Web 运行变量。日志中即使显示发现 `.env`，它也不是 standalone、export 或 Tauri 构建的配置来源。

## 3. Web 运行时行为

Web 生产部署使用 Next standalone 服务。构建时不加载 Web `.env`；服务启动后才从部署目录的 `.env` 读取配置。公开配置通过服务端动态渲染的 `meta[name="runtime-config"]` 和 `GET /api/config` 下发给浏览器。改动 Web `.env` 后重启服务并刷新页面即可，不需要重新编译前端。

服务端密钥只留在服务端。`runtime-config` 和 `/api/config` 仅允许返回浏览器所需的公开配置，不得包含 API Key、签名密钥或其他 secret。纯静态 `export` 没有 Next 服务端，不能动态读取部署机上的 `.env`。

## 4. 桌面运行时行为

桌面包是静态 Tauri 前端，不存在可读取服务器 `.env` 的 Web 服务进程。当前实现把 `.env.build` 中的公开配置嵌入静态资源，应用启动时从 HTML meta 读取；当前版本没有外部 `.env` 加载或服务地址设置页，因此当前版本修改服务地址仍需重新打包。

目标实现如下：

1. `.env.build` 中的服务地址作为安装包的首次启动默认值，不作为用户修改配置的唯一方式。
2. 桌面设置页提供可编辑的服务地址，至少覆盖 Router API、Router Portal、Warehouse/WebDAV 和 Node 身份认证服务地址及 WebDAV 前缀。
3. 设置保存到当前操作系统用户的 Chat 持久化配置中；应用启动时加载并覆盖包内默认值。不能要求用户编辑 `.env`、`.env.build` 或应用安装目录中的文件。
4. 设置页提供连接测试、输入校验和恢复包内默认值。保存后重新初始化受影响的服务客户端；若不能安全地热更新，则提示用户重启 Chat 后生效。
5. 用户覆盖在普通应用升级后继续保留；重置操作删除覆盖值并回到当前版本包内默认值。

桌面运行时配置优先级：

```text
用户在 Chat 设置页保存的覆盖值
    ↓
安装包内由 .env.build 提供的默认值
    ↓
代码安全默认值
```

设置页可变服务字段：

- `ROUTER_BACKEND_URL`
- `ROUTER_PORTAL_URL`
- `ROUTER_PORTAL_TOKEN_URL`
- `ROUTER_PORTAL_RECHARGE_URL`
- `WEBDAV_BACKEND_BASE_URL`
- `WEBDAV_BACKEND_PREFIX`
- `CENTRAL_UCAN_AUTH_BASE_URL`

以下字段属于应用身份/协议，不对普通用户开放修改：

- `CHAT_APPLICATION_UID`：Node 应用中心中 Chat 的稳定 `applications.uid`，决定登录身份、UCAN capability 和 Warehouse 应用空间。
- `CENTRAL_UCAN_REDIRECT_URI`：桌面回调固定为 `chat://localhost/central-ucan-callback.html`，必须和 Tauri 协议注册及 Node 应用中心配置匹配。
- 构建版本、应用签名和 updater 配置。

允许用户修改的服务 URL 是公开配置，不得在这些字段中存储或传递 API Key、访问令牌、数据库凭证、签名密钥等 secret。生产 HTTPS 校验、开发回环地址规则和 Warehouse CORS 要求由实现与部署文档共同定义。

## 5. 发布和运维流程

### Web standalone

```text
部署代码/standalone 产物一次
修改服务器 .env
重启 Chat Web 服务并刷新浏览器
```

Router、Warehouse 和 Node 地址属于 Web 运行时公开配置，可在服务器 `.env` 调整，不需要为地址变化重新构建 Web 代码。服务端私密变量仍只在 Node 进程中使用。

### 桌面应用

```text
.env.build 提供出厂默认值
构建并发布安装包
用户在 Chat 设置页按需覆盖服务地址
```

更改桌面包的出厂默认值仍需重建安装包；用户自己的地址调整通过设置页完成，不需要重新打包。更改 Chat 应用 UID、回调协议或代码版本属于发布变更，不能作为普通服务地址覆盖处理。

## 6. 当前状态与验收

截至本文更新时，Web standalone 的公开运行配置支持服务端 `.env` 动态生效；桌面端 `.env.build` 的公开值仍嵌入包内。桌面设置页覆盖功能尚未落地，实施完成前应在桌面运维文档中明确注明修改包内默认地址需要重新打包，不能提前按目标能力指导用户。

桌面设置页实现的验收条件：

- 用户能在设置页修改、保存并测试可变服务地址，不接触配置文件。
- 保存的值在应用重启和升级后保持，且只对当前桌面用户生效。
- 可恢复到当前安装包默认值。
- 改 Router、Warehouse 或 Node 地址后，受影响流程使用新地址；身份 UID 和回调协议不随之改变。
- secret 不进入桌面公开配置、设置页面服务地址存储或浏览器公开配置接口。
- Web `.env` 变更经重启和刷新生效，页面公开配置不被 CDN 或浏览器缓存为旧值。
