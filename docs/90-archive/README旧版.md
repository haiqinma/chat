### 3.3 不建议删除

目前没有发现可以直接删除且不会损失信息的现有 `docs/*.md` 文件。多数文档虽然数量多，但分别承担用户、部署、架构、运行机制、验收或规划职责；问题主要是入口分散和主题重叠，而不是内容完全无用。

## 4. 文档治理规则

1. 新增文档前，先判断是否能作为现有主文档的章节。
2. 方案类文档必须写明状态：`现状基线`、`设计阶段`、`实施中`、`已落地` 或 `归档`。
3. 架构变化先更新 [AI Native 能力分层架构](./AI-Native能力分层架构.md) 的版本记录，再补充专题方案。
4. README 只保留少量高频入口，完整索引放在本文档。
5. 删除文档前先确认 README、代码注释和其他文档没有引用。
