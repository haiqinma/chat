# 文档治理规范

## 文档类型

| 目录 | 内容 |
| --- | --- |
| `00-overview` | 总览、术语、治理规则 |
| `10-user` | 用户操作和故障排查 |
| `20-product` | 产品定位、能力边界、路线 |
| `30-architecture` | 系统设计、数据、身份、安全 |
| `40-development` | 开发、集成、测试、验收 |
| `50-operations` | 配置、部署、发版、恢复 |
| `60-skills-marketplace` | Skill、Tool、Marketplace |
| `90-archive` | 已失效但需追溯的内容 |

跨主题内容只保留一个主文档，其他文档使用链接引用，不复制同一事实。

## 状态与维护

方案类文档在标题下声明：

```text
> 状态：草案 | 已采用 | 实施中 | 已废弃
> 维护者：模块或团队
> 最后核验：YYYY-MM-DD
```

用户和操作文档默认描述当前行为；未落地方案不得写成现状。每次行为、配置或发布流程变化时，在同一变更中更新对应文档。

## 命名与资源

- 文件名使用稳定主题名，不加入日期、版本号或“最终版”。
- 每篇文档只有一个一级标题。
- 图片统一放在 `assets/images/<topic>/`。
- 新文档必须加入 `docs/README.md`。

## 评审与归档

身份、安全、数据兼容和发布流程文档需要模块维护者评审。每次发版前核验用户指南、运行时配置、验收清单和安全清单。失效文档迁入 `90-archive`，顶部注明替代文档和归档日期；无追溯价值的草稿可直接删除。

## 事实来源

环境变量以代码配置定义为准，API 以类型或 schema 为准，测试清单不等同于自动化覆盖。实现和文档不一致时，应在同一变更中修正并说明原因。
